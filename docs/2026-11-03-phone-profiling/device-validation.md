# PC 없이 안전한 성능 진단 전달하기

새 디버그 APK의 진단 보기·복사 기능은 구현되었다. 아래 Galaxy S23 Ultra 실제 수집·복사·사용자 전달 절차는 아직 실행하지 않았다. 계정 없는 API 35 에뮬레이터의 합성 검증과 실제 Health Connect·Google OAuth·private Drive 검증은 구분한다. 이전 원본 비교/D08 확인은 유지하며 다시 요구하지 않는다. 나머지 [기존 P0 미확인](../P0/device-acceptance.md), TalkBack과 [상단 가림 backlog](../backlog/layout-refinement.md)는 그대로 남는다.

## 준비와 수집

1. 새 디버그 APK인지, 설치 소스 revision과 기존 고정 서명이 맞는지 비공개로 확인한다. release에는 진단 버튼이 없다. 서명 변경·재설치로 계정/로컬 상태를 잃지 않도록 기존 설치 절차를 따른다. 이 기능은 새 권한·OAuth scope를 요구하지 않는다.
2. 평소처럼 Health Connect 권한과 비공개 업로드 동의를 확인하고 **Google 권한 확인 → 업로드 계속**으로 수동 동기화한다. 앱을 전경에 유지하고 성공·실패·취소를 구분한다. 진단 보기는 동기화를 대신 시작하지 않는다.
3. 시도가 끝나면 화면을 스크롤해 **성능 진단 보기**를 누른다. 인증 대기, 업로드 계속 대기, 전체 실행 및 각 하위 단계 시간을 확인한다. **표시할 진단이 없습니다.** 또는 **진단 수집 중…**이면 복사할 완료 요약이 없는 상태다. 과거 성공이나 측정된 0으로 해석하지 않는다.
4. **안전한 진단 요약 복사**를 직접 누른다. **진단 요약을 복사했습니다.**는 클립보드 쓰기 호출이 오류 없이 반환했다는 뜻이며 외부 전달 완료는 아니다. **진단 요약을 복사하지 못했습니다. 다시 눌러 주세요.**가 나오면 필요할 때 직접 다시 누른다. 자동 재시도는 없고 복사 실패는 동기화 결과·확인된 부분 업로드 수·이력·취소 전파를 바꾸지 않는다.
5. 전달 입력란에 붙여넣고 **보내기 전에** 아래 고정 24행과 6개 숫자 열을 확인한다. 다른 클립보드 내용이거나 allowlist 밖 정보가 보이면 전송하지 않는다. 앱/건강 화면, CSV, 원시 로그나 스크린샷을 첨부하지 않는다.
6. 확인한 안전 요약만 사용자가 선택한 대화에 직접 보낸다. 앱에는 자동 외부 전송·진단 파일 저장·Drive 진단 업로드가 없다. 전달 뒤 클립보드 처리는 사용자가 OS 기능으로 확인한다. 앱 내 진단 삭제가 시스템 클립보드를 지운다고 가정하지 않는다.

## 공유 전 고정 형식 확인

헤더 없이 24행이다. 각 행은 `라벨 started completed failed cancelled elapsed_ns active`이며 라벨 뒤 숫자가 정확히 6개다. 숫자는 음이 아닌 정수, `active`는 `0` 또는 `1`이다. 호출 횟수는 계측된 단계/작업 호출 수이며 건강 기록 건수가 아니다.

| 행 | 라벨 순서 |
|---|---|
| 1–10: 단계 | AUTHORIZATION_HISTORY, AUTHORIZATION_WAIT, CONTINUE_WAIT, EXECUTION, START_HISTORY, HEALTH_READ, NORMALIZE, CSV_EXPORT, DRIVE_TOTAL, TERMINAL_HISTORY |
| 11–17: Drive 업무 operation | APP_FOLDER_LOOKUP, APP_FOLDER_CREATE, DATASET_FOLDER_LOOKUP, DATASET_FOLDER_CREATE, FILE_LOOKUP, FILE_CREATE, FILE_UPDATE |
| 18–24: transport request | 11–17행과 같은 순서 |

operation과 request는 같은 라벨을 쓰므로 행 위치로 구분한다. 건강 값·건강 기록 건수·보고 날짜·절대 시각·계정/기기/Drive 파일/레코드 식별자·토큰·URL/query·파일명·공급자 오류 원문·로그 접두사가 없어야 한다. 이 문서에는 실제 측정 요약을 붙이지 않는다.

## 시간 읽는 법

- `측정 없음`은 유효 관측이 없다는 뜻이다. 시계 실패로 관측이 폐기된 경우도 있으므로 업무가 실행되지 않았다고 단정하지 않는다. `미완료`/`active=1`은 아직 종료되지 않은 관측이다.
- 종결된 실제 0은 `0 ms`이고 양수지만 1ms보다 작으면 `1 ms 미만`이다. 실패·취소 표시는 계측 구간 결과다. 경과 시간만으로 업로드 성공이나 건강 자료 완전성을 판단하지 않는다.
- AUTHORIZATION_WAIT는 인증 시작부터 콜백 검증/처리까지이고 Google 서버 시간만이 아니다. CONTINUE_WAIT는 인증 수락 이력/UI 처리와 사용자의 계속 대기를 포함할 수 있다. 둘은 EXECUTION과 분리한다.
- EXECUTION 안에는 START_HISTORY, HEALTH_READ, NORMALIZE, CSV_EXPORT, DRIVE_TOTAL, TERMINAL_HISTORY가 포함된다. DRIVE_TOTAL 안에 업무 operation이, 그 안에 request가 중첩된다. 단계·operation·request를 더해 총시간이나 요청 수를 만들지 않는다. 요청 계측에는 transport와 HTTP/JSON 응답 검증이 포함되며 이후 private 대상 거부로 operation만 실패할 수 있다.
- 같은 기기/버전·전경·권한·데이터량 범주·네트워크·첫 생성/갱신·인증 조건을 고정하고 준비 실행 제외 수와 반복 수를 미리 정한다. 실패·취소·미관측·미완료는 완료 표본과 분리한다. 동일 조건 완료 표본의 분모·제외 이유와 함께 p50/p95를 계산한다. 아직 실제 기기 시간은 없으므로 병목·개선율·SLA·속도 향상을 진단하지 않는다. 자세한 [기존 측정 해석과 ADB 대안](../2026-11-02-sync-profiling/device-profiling.md)을 유지한다.

## 서로 다른 수명

| 대상 | 유지 범위와 한계 |
|---|---|
| 앱의 진단 | 최근 수동 시도 1건의 제한된 불변 요약만 화면 모델 메모리에 둔다. 유효한 새 시도나 동의 변경/로컬 상태 무효화 시 이전 요약을 지우고 늦은 콜백이 복원하지 못한다. 파일·저장 상태·복원 번들·이력 DB에 저장하지 않는다. |
| 화면 모델·프로세스 | 같은 화면 모델이 유지되는 화면 재생성에서는 남을 수 있다. 새 화면 모델·새 프로세스는 진단 없음으로 시작한다. 펼침 여부 복원은 진단 내용 복원이 아니다. 프로세스 종료 전에 요약을 얻는다는 보장도 없다. |
| 시스템 클립보드 | 명시적으로 복사한 별도 OS 상태다. 새 시도·앱 내 삭제·프로세스 종료 뒤에도 남을 수 있다. OS/키보드/다른 앱의 열람·보관·자동 삭제 시점은 앱이 보장하지 않는다. API 35 합성 쓰기 성공을 Galaxy나 모든 OS 동작의 보장으로 확대하지 않는다. |

## 현재 확인과 남은 확인

[실행 보고](execution-report.md)의 JVM109개와 최종 API 35 Android55개·host20개가 통과했다. 합성 Compose의 밝음/어두움 및 글자 1배/2배에서 진단 버튼·텍스트 접근을 확인했으며 실제 Galaxy/TalkBack 접근성은 미확인이다. 실제 기기 수집·사용자 전달, 실제 기기의 클립보드, OAuth 완료·실측 p50/p95는 아직 미확인이다. 실제 수집 후에도 기존 private Drive·동일 파일 갱신·권한/취소·이력 수용 결과를 진단 시간으로 대체하지 않는다.
